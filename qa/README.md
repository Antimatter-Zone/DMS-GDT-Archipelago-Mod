# Two local private smoke clients

AMZ Hub stages each user's licensed local GDT installation into a separate
profile instance. No game files or native libraries belong in a DMS release.

The DMS-only client payload is:

```text
mods/DMSArchipelago/package.json
mods/DMSArchipelago/main.js
mods/DMSArchipelago/contract.js
mods/DMSArchipelago/bridge.js
qa/smoke-bootstrap.js
qa/smoke-storage.js
```

Hub creates an instance containing `game/`, `saves/`, and `chromium/`. The game
copy has a unique manifest name and launches with node-webkit 0.8.6's legacy
`--data-path=<instance>/chromium`. Saves survive replacement of `game/`.

In the staged HTML only, replace the consecutive `compressed/codeNw.js`,
`js/GDT.js`, and `js/modSupport.js` script tags with one script tag loading
`./qa/smoke-bootstrap.js`. The bootstrap loads the original scripts only after
verifying the target source SHA, native hook installation and a local read/write
sentinel. Ordinary mod load occurs too late to isolate game storage.

Hub writes `game/qa/smoke-profile.json`:

```json
{"schemaVersion":1,"profileId":"smoke-a","saveDirectory":"<absolute instance path>/saves"}
```

The save directory must be the exact sibling of `game/`; it and existing save
files cannot be symlinks. All native save reads/writes use that private folder.
Steam initialization remains native, while smoke achievement writes are
suppressed. No original cloud save function is called and no Steam settings are
changed. If isolation fails, the game code does not load.

The bootstrap enables only the game's installed `gdt-modAPI` 0.1.2 and DMS mod.
Hub also writes its credential-bearing mod configuration as described in
[the bridge contract](../BRIDGE-CONTRACT.md); that file is never packaged.

Acceptance requires two independently logged-in AMZ profiles, both slot-bound
fresh saves, one native game release in each client sending a Topic pack to the
other, a working hint, and reconnect/save-reload without duplicate effects.
The target smoke seed is generated by the APWorld repository's `smoke/players`
YAMLs using seed `20261004` and `--plando items`.
